FOR WHOEVER ADDS THE RECORDS
================================================================

Four records on ferrario.com. The "Name" column is the short form most DNS
panels expect; if yours wants the full name instead, use the FQDN line. Please
don't enter both, or it doubles up the domain and won't verify.


1. DKIM signing key

   Type:  TXT
   Name:  resend._domainkey
   FQDN:  resend._domainkey.ferrario.com
   TTL:   Auto / default

   Value - must be one unbroken line, no spaces or line breaks:

<<< PASTE THE DKIM VALUE FROM RESEND AFTER ADDING ferrario.com >>>


2. Return-Path mail exchanger

   Type:      MX
   Name:      send
   FQDN:      send.ferrario.com
   Value:     feedback-smtp.us-east-1.amazonses.com
   Priority:  10
   TTL:       Auto / default

   This is on the "send" subdomain and does not affect the MX records that
   deliver your normal mail.


3. SPF for the Return-Path subdomain

   Type:  TXT
   Name:  send
   FQDN:  send.ferrario.com
   Value: v=spf1 include:amazonses.com ~all
   TTL:   Auto / default

   IMPORTANT: this belongs on "send", not on the root domain. Adding a second
   SPF record to ferrario.com itself would break existing mail flow.


4. Sending endpoint

   Type:  CNAME
   Name:  rsend
   FQDN:  rsend.ferrario.com
   Value: send.forge.rmta.net
   TTL:   Auto / default


Two things that commonly go wrong:

  - Some panels append the domain automatically. Entering the FQDN in a panel
    that already appends it produces
    resend._domainkey.ferrario.com.ferrario.com, which won't verify.
  - The DKIM value in record 1 must stay on one line. Copying it out of a
    formatted document can introduce spaces or line breaks.

Reply once they're in and we'll run verification, which takes a few minutes
after DNS propagates. If any of these conflict with a record you already have,

ONE THING TO CHECK RATHER THAN ADD
----------------------------------

If ferrario.com already publishes a DMARC record at _dmarc.ferrario.com, please
send us what it says. We are NOT asking you to add or change one.

Two reasons it matters. If the policy is p=quarantine or p=reject, we want to
confirm alignment before the first send rather than discover it from a
rejection. And a domain can only have one DMARC record, exactly like SPF, so if
one already exists then adding a second would invalidate both. Same trap as
record 3 above, different record.
