# DriveOne Design System

Co-branded dealer email design system and campaign automation for the DriveOne VSC
post sale program.

A **service drive follow up**: ten emails over 60 days, sent on a dealership's behalf to
its own service customers who just had a visit and have no vehicle service contract on
file. Each email carries that customer's real vehicle, their real visit, and a real monthly
price with a buy button.

Product: **DriveOne VSC, Platinum**, administered by Ascent Administration Services, LLC,
and in New York by ORIAS Warranty Services. Every offer claim in the campaign is quoted
from or directly supported by the executed contract form.

## What is here

```
brand/
  driveone.tokens.json        DriveOne master tokens. Locked. Never edit per dealer.
  offer.json                  Product facts. Become merge defaults, baked in at build.
  dealers/<dealer>.json       THE ONLY FILE THAT DIFFERS PER ROOFTOP.

email/
  copy/campaign.json          All ten emails. Shared across every dealership.
  build.mjs                   Renders tokens + dealer + offer + copy into email safe HTML.
  dist/<dealer>/              Built templates, merge tags intact. Generated.

n8n/
  sql/schema.sql              Durable enrollment state.
  sql/campaign-role.sql       Read-only source role, for a split-project setup only.
  build-workflows.mjs         Generates the workflows from the same copy deck.
  verify.mjs                  Asserts behaviour on the generated workflows.
  workflows/<dealer>/         Five importable workflow JSON files. Generated.

preview/                      Review galleries plus sample-data previews. Generated.
scripts/check.mjs             Pre-send guard. Run it before every launch.
docs/                         Setup, data contract, deliverability, per-dealer launch state.
.claude/skills/               The campaign operations manual.
```

Everything under `email/dist/`, `preview/` and `n8n/workflows/` is generated by
`npm run build` and is not committed. `brand/` and `email/copy/` are the sources of truth.

## Commands

```bash
npm run build                      # every dealership: emails, workflows, verify, guard
npm run build:ferrario-ford        # just one
npm run check -- <dealer>          # guard, warns on unfinished setup
npm run check:launch -- <dealer>   # guard, FAILS on unfinished setup. Run before sending.
npm run verify -- <dealer>         # behavioural checks on the generated workflows
npm run simulate                   # cohort size against the daily cap
npm run publish:templates -- <dealer> > /tmp/t.sql
npm run publish:static             # assemble public/ for Vercel
```

## One engine, one deck, one file per rooftop

Adding a dealership is a new file in `brand/dealers/`, not a copy of the repo.
`docs/ADDING-A-DEALERSHIP.md` is the procedure.

This repo briefly was two repos, and the merge that ended that is the reason for the rule.
In the thirty hours before the fork was cut, the shared engine took thirteen commits,
including a cadence bug that flattened a ten email sequence into a flat weekly drip, a
`$json` reference that would have killed every inbound event, and a positional parameter
bug that silently discarded rows. Every one would have needed applying twice, and not one
of them errored at runtime. A drifted copy does not announce itself.

The cost of sharing is the other direction: `email/copy/campaign.json` is one deck, so
editing it edits every dealership's campaign. If a rooftop needs its own arguments, that is
a real change to make and it needs somewhere to live.

## The checks are not decoration

`n8n/verify.mjs` asserts behaviour rather than shape, and every check in it exists because
the bug it catches actually shipped. It reads the output of the generated code rather than
its text wherever it can, because it is easy to verify that a change was *applied* and much
harder to verify that it produced the right *behaviour*.

`scripts/check.mjs` refuses to ship copy containing an em dash or an exclamation point,
copy that calls the DriveOne product a warranty, a template over Gmail's 102KB clip
threshold, a template with no unsubscribe link, a monthly price shown without its payment
term, and an unknown merge tag. In `--launch` mode it also fails on an unconfirmed postal
address, service phone, reply-to or quote URL.
