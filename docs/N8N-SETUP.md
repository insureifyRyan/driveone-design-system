# n8n setup

Four workflows. Import in order. All are generated by `npm run build:n8n` from
`email/copy/campaign.json`, so never hand edit the JSON: edit the deck and regenerate.

```
01-intake.json        DMS repair order feed  ->  eligibility  ->  enrollment row
02-scheduler.json     hourly  ->  claim whatever is due  ->  send  ->  advance state
03-events.json        purchase / unsubscribe / bounce  ->  exit and suppress
04-error-handler.json any failure in any of the above  ->  Slack alert
```

## Why this is not one long Wait node chain

A 60 day drip built on Wait nodes is the obvious way to do this and it is a trap. Wait
nodes hold execution state in the n8n instance. Restart n8n, upgrade it, redeploy it or
lose the container, and every contact mid-flight is gone silently. You also cannot query
"who is on step 6," cannot pause one contact, and cannot change cadence for people
already enrolled.

This uses a durable state machine instead. The enrollment row in Postgres is the truth.
n8n is stateless and disposable. You can destroy and rebuild the n8n instance mid
campaign and nothing is lost.

Concretely that buys you:

- **Restart safety.** State lives in the database, not in an execution.
- **No double sends.** The scheduler claims rows with a single atomic `update ...
  returning` using `for update skip locked`, and leases them two hours forward. Two
  schedulers racing cannot pick the same row. A crashed run retries in two hours instead
  of stranding the contact or sending twice. `vsc_send_log` has a `(enrollment_id, step)`
  unique constraint as a second line of defence.
- **Late sends do not compress the cadence.** Each next send is computed from the
  enrollment date, not from "now," so an outage delays one email rather than bunching the
  remaining nine.
- **Exits are immediate.** Suppression is re-checked inside the claim query, not only at
  intake. Someone who unsubscribes on day 11 of 60 gets nothing further, with no sweep
  job needed.
- **Quiet hours are free.** Outside the 09:00 to 19:00 dealer local window the prepare
  step emits nothing, the lease expires, and the row is naturally retried in the next
  window.
- **Adding dealership two is a copy.** Every workflow is parameterized on `dealer_id`.

## Install

**1. Database.** Run `n8n/sql/schema.sql` against Postgres. Supabase works. Swapping to
another store means changing only the Postgres nodes.

**2. Credentials.** Create these in n8n, then replace the `REPLACE_*_CRED_ID` placeholders
on import (n8n prompts for each on first open).

| Placeholder | Type | Used by |
|---|---|---|
| `REPLACE_PG_CRED_ID` | Postgres | all |
| `REPLACE_DMS_AUTH_CRED_ID` | Header Auth | 01 webhook |
| `REPLACE_DMS_API_CRED_ID` | Header Auth | 01 nightly pull |
| `REPLACE_EVENT_AUTH_CRED_ID` | Header Auth | 03 webhook |

**3. Environment variables.**

| Variable | Example | Notes |
|---|---|---|
| `TEMPLATE_BASE_URL` | `https://<project>.vercel.app/templates` | Where `email/dist/*.html` is served. Vercel config is in the repo. |
| `RESEND_API_KEY` | `re_...` | |
| `SEND_FROM` | `Bob Johnson Service <service@mail.bobjohnson...>` | Must be a dealer domain. See open item 4. |
| `SEND_REPLY_TO` | `service@...` | A monitored mailbox. |
| `UNSUBSCRIBE_URL_BASE` | `https://.../unsubscribe` | Must honour one click. |
| `UNSUBSCRIBE_MAILBOX` | `unsubscribe@...` | For the `List-Unsubscribe` mailto. |
| `PREFERENCES_URL_BASE` | `https://.../preferences` | |
| `QUOTE_URL_BASE` | `https://...` | Quote links are built as `{base}/{dealer}/quote?vin=&k=`. |
| `DEALER_TZ` | `America/New_York` | Bob Johnson is Rochester NY. |
| `DMS_VENDOR` | `generic` | Selects the field map in workflow 01. |
| `DMS_API_BASE` | | Only for the nightly pull fallback. |
| `SLACK_ALERT_WEBHOOK` | | Workflow 04. |

**4. Error workflow.** In each of workflows 01 to 03: Settings, Error Workflow, select
`DriveOne VSC 04 Error Handler`. Without this, failures are silent.

**5. Test before activating.** Everything imports inactive. Post one fake RO to the
workflow 01 webhook, confirm a row appears in `vsc_enrollment`, then set that row's
`next_send_at` to `now()` and run workflow 02 manually.

## Adding a second DMS

Edit one node: `Normalize RO Payload` in workflow 01. Add a block to `MAPPINGS` keyed by
vendor and set `DMS_VENDOR`. Blocks inherit nothing from each other, so a wrong key in
one vendor can never break another. No other node reads raw DMS fields.

## Adding a second dealership

1. Copy `brand/dealers/bob-johnson.json` to `brand/dealers/<new>.json` and fill it in.
2. `node email/build.mjs <new>`
3. `node n8n/build-workflows.mjs` (point it at the new dealer file)
4. Import the four workflows under a new `dealer:<new>` tag.

Enrollment rows are keyed by `dealer_id`, so dealerships share the database without
touching each other.

## Changing the cadence

Edit `sendDay` in `email/copy/campaign.json`, run `npm run build`, re-import workflow 02.
The schedule is compiled into the workflow from the deck, which is the whole reason the
workflows are generated rather than hand built. Contacts already enrolled pick up the new
cadence on their next step, because the next send time is computed at send time rather
than at enrollment.
